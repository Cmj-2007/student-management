# 考核项目一：学生管理系统业务开发

#### 一、项目概述

本项目是一个基于控制台的**学生管理系统**，采用经典的三层架构设计（Controller-Service-Mapper），要求你完成缺失的业务逻辑实现。

#### 二、项目架构说明

```
学生管理系统架构
├── Controller层（控制层）- 已完成
│   └── StudentController.java - 处理用户输入输出，调用Service层
├── Service层（业务逻辑层）- 部分完成，需要你补全
│   ├── StudentService.java - 业务接口定义（已完成）
│   └── StudentServiceImpl.java - 业务逻辑实现（新增功能已完成，其他待完成）
├── Mapper层（数据访问层）- 需要你完成
│   ├── StudentMapper.java - 数据操作接口定义（仅有新增方法，其他方法需补充）
│   └── StudentMapperImpl.java - 数据操作实现（仅有新增方法，其他方法需补充）
├── Entity层（实体层）- 已完成
│   └── Student.java - 学生实体类
└── Main.java - 程序入口（已完成）
```

#### 三、功能需求

系统需要实现以下5个核心功能：

1. **新增学生** - 添加新的学生信息到系统（**已完成，供参考**）
2. **查询学生** - 支持按学号查询、按班级查询、查询所有学生（**待完成**）
3. **修改学生信息** - 根据学号修改学生的其他信息（**待完成**）
4. **删除学生** - 根据学号删除学生记录（**待完成**）
5. **退出系统** - 安全退出程序（**已完成**）

#### 四、数据存储方式

- 使用 `HashMap<String, Student>` 模拟数据库
- Key：学号（唯一标识）
- Value：学生对象
- 数据仅在程序运行期间有效（内存存储）

##### 5.2 完善Service层（业务逻辑层）

**文件：`service/StudentServiceImpl.java`**
在每个TODO位置实现完整的业务逻辑，**参考已完成的 `addStudent`方法**，包括：

1. **参数校验**：检查输入参数是否合法
2. **业务规则验证**：确保符合业务要求
3. **调用Mapper层**：执行数据操作
4. **结果处理**：将操作结果转换为用户友好的提示信息

**需要完成的方法：**

- `getStudentByStudentId(String studentId)`

  - 校验学号是否为空
  - 调用Mapper查询
  - 返回格式化的学生信息或"学生不存在"
- `getStudentsByClassName(String className)`

  - 校验班级名称是否为空
  - 调用Mapper查询班级学生列表
  - 返回格式化的学生列表或"该班级暂无学生"
- `getAllStudents()`
  - 调用Mapper查询所有学生
  - 返回格式化的所有学生信息或"暂无学生数据"
- `updateStudent(Student student)`

  - 校验学号是否存在
  - 校验要修改的字段（性别、年龄等规则同新增）
  - 只更新非空字段（空字段表示不修改）
  - 返回"修改成功"或具体错误信息
- `deleteStudent(String studentId)`

  - 校验学号是否为空
  - 检查学生是否存在
  - 调用Mapper删除
  - 返回"删除成功"或"学生不存在"

#### 六、业务校验规则

**请仔细研究已完成的 `addStudent`方法**，在其他方法中遵循相同的校验标准：

1. **学号**：不能为空，且唯一
2. **姓名**：不能为空
3. **性别**：只能是"男"或"女"
4. **年龄**：必须在18-25岁之间
5. **班级**：可以为空（修改时）
6. **专业**：可以为空（修改时）

**重要提示**：`addStudent`方法展示了完整的参数校验、业务逻辑处理和返回值格式，是你完成其他方法的最佳参考示例。

#### 七、返回值格式要求

所有Service方法都返回 `String`类型，用于向用户展示操作结果：

- **成功操作**：返回简洁的成功提示，如"查询成功！"、"修改成功！"
- **失败操作**：返回具体的错误信息，如"学号不能为空！"、"学生不存在！"
- **查询结果**：返回格式化的学生信息字符串

**建议的格式化示例：**

```java
// 单个学生信息
"学号：2024001，姓名：张三，性别：男，年龄：20，班级：计算机1班，专业：计算机科学与技术"

// 多个学生信息
"共找到3名学生：\n" +
"学号：2024001，姓名：张三，性别：男，年龄：20，班级：计算机1班，专业：计算机科学与技术\n" +
"学号：2024002，姓名：李四，性别：女，年龄：19，班级：计算机1班，专业：计算机科学与技术\n" +
"学号：2024003，姓名：王五，性别：男，年龄：21，班级：计算机1班，专业：计算机科学与技术"
```

#### 八、关于 AI 辅助编程的特别说明（必读）

在这个 AI 时代，我们**非常鼓励甚至推荐**大家使用 AI 工具（如通义千问、豆包、ChatGPT）或 AI 编程插件（如 GitHub Copilot、通义灵码、Codeium 等）来辅助完成本次考核。能够熟练利用 AI 解决问题，是现代程序员必备的核心技能。

但在使用 AI 时，请务必遵守以下两个原则：

1. **你必须掌握代码的“解释权”**
   你是这个项目的真正主导者，AI 只是你的代码打字员。**绝对不要把连你自己都看不懂的代码直接复制粘贴进来。** 在后续的面试答辩环节，学长学姐会随机挑选几行代码，让你解释它的业务逻辑。比起“一段由 AI 生成的完美无缺但你看不懂的代码”，我们更欣赏“一段哪怕有点小 Bug，但你能清晰讲出自己思考过程的代码”。
2. **切忌“一口吃成个胖子”（控制生成粒度）**
   **千万不要**直接把整个题目要求或一整个 Java 文件扔给 AI，让它一次性帮你写完所有的代码。如果你一次性生成太多代码，你将完全**失去对整个工程的控制力**。这不仅不利于你理解 Controller-Service-Mapper 的三层架构，而且一旦代码报错，面对大段未经消化的代码，你的调试难度和学习成本将会成倍增加。

   **正确的做法是：** 遇到卡壳的地方，一个方法、一个业务逻辑地去问 AI。例如：“在 Java 中，如何判断一个 `studentId` 是否已经存在于 HashMap 中？” 这样一点点拼装，才是真正吸收知识的过程。
